# Vidmoat Skills

Video editing craft, written down as [Agent Skills](https://agentskills.io): how
to caption so people can read it, how to sit music under a voice, and more.
Each skill is a folder with a `SKILL.md` that any skills-aware agent can load
when the task calls for it: Claude Code, Codex, GitHub Copilot, Cursor, Gemini
CLI and others.

The skills are tool-agnostic. They work in whatever editor you use, and every
one has a path that needs nothing but ffmpeg. They come from the editing
guidance inside [Vidmoat](https://vidmoat.com), an AI video editor; the editor
itself stays closed, the craft is open.

## What is in a skill

```
skills/core/caption-styling/
  SKILL.md              defaults, workflow, gotchas (loaded when relevant)
  references/           detail the agent reads only when it needs it
  scripts/              small standard-library tools (no network, no installs)
  evals/evals.json      trigger cases and graded output cases
```

Every skill has a **Gotchas** section of corrections learned from real
failures, and an **eval suite** that checks both that the skill loads when it
should (and stays out of the way on near misses) and that answers with the
skill beat answers without it.

`core` skills are curated by maintainers and are the only skills Vidmoat's

linted the same way, and never loaded automatically by Vidmoat.

## Install

### Claude Code

```text
/plugin marketplace add vidmoat/skills
/plugin install vidmoat-core@vidmoat-skills
```

From a shell: `claude plugin marketplace add vidmoat/skills`. To stay on
released versions only, add `vidmoat/skills#stable` instead. Community skills
are a separate plugin, `vidmoat-community@vidmoat-skills`, so you opt in to
them deliberately.

To use a single skill without the plugin system, copy its folder into
`.claude/skills/` in your project or `~/.claude/skills/` for every project.

### Codex, GitHub Copilot, Cursor, Gemini CLI and other clients

Most clients read skills from a skills directory. `.agents/skills/` (in a
project) and `~/.agents/skills/` (for your user) are the shared convention at
the time of writing; check your client's documentation for its current paths.

```bash
git clone --depth 1 --branch stable https://github.com/vidmoat/skills.git vidmoat-skills
mkdir -p .agents/skills
cp -r vidmoat-skills/skills/core/caption-styling .agents/skills/
```

| Client | Project folder | User folder |
| --- | --- | --- |
| Codex | `.agents/skills/` | `~/.agents/skills/` |
| GitHub Copilot | `.github/skills/` or `.agents/skills/` | `~/.copilot/skills/` or `~/.agents/skills/` |
| Cursor | `.cursor/skills/` or `.agents/skills/` | see Cursor docs |
| Gemini CLI | `.gemini/skills/` or `.agents/skills/` | `~/.gemini/skills/` or `~/.agents/skills/` |

Community installers that understand this layout, such as the `skills` CLI
(`npx skills add vidmoat/skills`), should also work. We do not maintain them;
read what they install before you run them.

### Pinning for production

If you load these skills into a product, pin an exact commit or a release
archive and verify its checksum. See [docs/consuming.md](docs/consuming.md).

## Contributing

New skills, fixes and gotchas from real failures are welcome. In short:

1. Open an issue with the **New skill** or **Gotcha report** template first.
2. Add your skill under `skills/community/<name>/` with `SKILL.md`, a Gotchas
   section and `evals/evals.json` (trigger cases with near-miss negatives, and
   output cases with assertions).
3. Run `npm test` (Node 20 or newer, no dependencies) and fix what it reports.
4. Sign off every commit (`git commit -s`): we use the
   [Developer Certificate of Origin](https://developercertificate.org), not a CLA.

Read [CONTRIBUTING.md](CONTRIBUTING.md) for the full guide and style rules, and
[docs/authoring.md](docs/authoring.md) for how to write a skill that helps.
Please also read the [Code of Conduct](CODE_OF_CONDUCT.md).

## Security

Skills are instructions an agent follows, so this repository treats skill text
like code: hidden Unicode, HTML comments, network calls and package installs in
scripts, and prompt-injection phrasing all fail CI. Report a vulnerability
privately as described in [SECURITY.md](SECURITY.md); the threat model is in
[docs/security.md](docs/security.md).
